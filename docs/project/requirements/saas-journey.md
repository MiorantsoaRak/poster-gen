# Simpler poster and publishing journeys

**Status** Approved for design, 2026-11-22, on the owner’s « continue » after the requirements handoff. Applies to shop and operator UI. [Review and screen inventory](../reviews/saas-ux-2026-11-22.md). Existing service, offer, credit and publishing rules remain binding.

| ID | Acceptance criterion |
|---|---|
| R-JOURNEY-001 | On a 360 px phone and desktop, a new shop can open creation from Accueil. A returning shop with a poster awaiting review sees an identifiable poster and its next action before healthy balance detail. With publishing enabled the shop reaches Publier from main navigation; Styles, credits, account and archived work remain reachable. Failed reads are labelled and retryable. |
| R-JOURNEY-002 | Given valid offer inputs and saved shop and text defaults, the guided user reaches the generation decision without advancing through unchanged Textes and Boutique pages. They can inspect and change every original option. Both guided and message users see the exact offer, chosen format and applicable cost before committing. Copying with a new photo preserves the source poster and requires an explicit first generation. |
| R-JOURNEY-003 | Owner-approved amendment, 2026-11-22. In both creation paths, review the selected generated product against its source photo and price on the exact final PNG. The seller can explicitly confirm the shown file for later use in Mes affiches. Downloading or preparing a Facebook post also accepts it in one action, with button labels that name the confirmation. Preparing a post never sends it. Keep correction, rejection, comparison, historical versions and native sharing. Opening, dismissing or failing a preview never approves it. A changed poster requires a current preview. Reuse an unchanged confirmed file. |
| R-JOURNEY-004 | After current-file confirmation, the PNG is accessible without a caption or connection. Where eligible, the direct Page composer opens with that poster selected. Native sharing and local caption editing remain available and labelled by purpose. Historical downloads identify the earlier file and cannot be mistaken for a current Page candidate. |
| R-JOURNEY-005 | For a missing candidate the picker identifies the poster, reason and applicable next step. Completing a check or connecting a Page permits return to the originating post with ordered choices and description intact. A changed item needs revalidation. Preserve description-first, order, per-shop cap, explicit destination confirmation and recovery of pending/unknown outcomes even after disconnection. |
| R-JOURNEY-006 | In the operator console, an unresolved financial action is reachable before summary metrics or past activity on a phone. Access, history, grants, corrections, repayment, transfers and service controls remain available. Each financial or account-changing confirmation names its target and effect. Retrying an uncertain payment or grant keeps its identity. |
| R-JOURNEY-007 | Both themes support the full paths at 360, 768 and 1440 px, keyboard-only navigation, labelled controls, visible focus and 44 px touch targets. Long product/Page names, pending operations, error states and phone keyboard do not hide the next action. Role-specific language, existing route access and independently themed poster art are preserved. |

Before design, reconcile the changes in navigation, guided ordering, output hierarchy and operator overview with the currently approved poster-editor, app-redesign, share-poster and dashboard requirements. Carry the owner’s description-first, ordering and publishing-confirmation decisions forward.
