# Interface polish — design review, round 1 (Codex, 2026-11-20)

On design v1. Every finding was taken into v2 (the table « What the two reviews changed » in [designs/interface-polish.md](../designs/interface-polish.md)); v2 was not reviewed again.

**REJECT — revise D-POLISH-002 and D-POLISH-003 before implementation.** The proposed contrast test has a dark-theme assertion that cannot pass with the approved palette. Other assertions can pass with an unreadable field, a missing chat heading, clipped navigation text, or the wrong five operator sessions. The Signal colours, Figtree, existing routes and creator credits panel can all be retained.

I reviewed the working tree. It already contains uncommitted branding changes, so I distinguish the current files from the proposal where they differ.

### High severity

1. **The dark focus-ring requirement is internally impossible.** Design lines 46–52 set dark `--text` to Warm Paper and `--hue` to Signal Yellow. Line 84 requires that pair to reach 3:1. It is **1.43:1**. The actual focus rule has a 2 px offset, so its adjacent colour is usually the surface *outside* the button. The yellow fill also has only 1.43:1 against Warm Paper, which matters for the project's explicit 3:1 boundary requirement. **Fix:** specify a concrete light-theme `--accent-edge` and hover colour. Measure the border against the surrounding surface and the offset ring against the pixels it replaces. Where a ring really touches yellow, use charcoal or a two-colour indicator. Cover the borderless chat Send button and the later `.download-button` border shorthand, which overrides the earlier border colour. Its existing text walk skips placeholders and accepts 3:1 for large text, while R-POLISH-002 requires 4.5:1 for every text. Exercise both normal glass and the solid fallback. This also preserves the earlier editor design’s explicit darkest/lightest-backdrop guarantee. ### Medium severity

6. **The bottom-bar test needs to distinguish visible text, accessible name and hit target.** Hiding “Mes” while leaving “Mes affiches 120” as the name can satisfy WCAG 2.5.3 because the visible word is contained in the name. Likewise for “117” in “117 crédits”. A real mismatch arises if the visible amount becomes `12 345` while `balanceLabel` still produces `12345 crédits`. Checking `scrollWidth` on the wrong span can also miss a child extending beyond its link, and checking height alone misses a narrow target. **Fix:** use the same formatted number in both representations, including the sign and singular for `-1`. Assert the visible text range fits inside the link on one line, the link measures at least 44 × 44, and the computed accessible name contains the visible text and retains its full meaning. Cover failed/unread balance, zero and negative balance. Keep the four-link dashboard, fifth creator link and separate editor-rail button distinct. Explicitly amend the earlier phone-nav decision to say counts become screen-reader-only at this width.
