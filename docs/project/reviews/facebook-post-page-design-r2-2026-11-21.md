# Design review r2 — A publish page: one Facebook post with one or several posters (v2)

Reviewer: Codex, read-only, fresh to the design, 2026-11-21. Verdict: REJECT (« the one-post model is sound »; three of round 1's ten closed, seven partial, of which three P1: the migration's join, the durable key, the task's ownership). Answered by v3 the same day; see r3.

The one-post model is sound. The blocker is migration 0019. Its `INNER JOIN` can silently turn a valid 0018 publication into a post with **zero items**, removing the protection against publishing that poster twice.

| Round 1 | Ruling | Trace and smallest fix |
|---|---|---|
| 1. Restore settlement | **CLOSED** | An `uploading` backup plus a kept `posting` or `unknown` now becomes `unknown`. Apply reconciliation before API startup. The restore script’s first `after-restore` invocation only prints the report, and the later `--apply` does the work. [Design §006](docs/project/designs/facebook-post-page.md#d-fb-post-006--what-is-said-and-what-is-restored-covers-r-fb-post-007) · [Restore script](deploy/restore.sh) |
| 2. Restore membership | **PARTIAL · P1** | New posts retain all item IDs. But today `_facebook` can restore a legacy publication when its poster survives and its newer confirmation does not. 0019 copies the parent, its join skips the item, and `DROP TABLE` discards the only remaining association. An `unknown` post then stops blocking that poster. Use a left join, permit a missing hash for historical items, and assert one item per legacy row before dropping. The kept-file reader also needs to recognize both schemas. A drop in a new forward migration is acceptable once this conversion is lossless. [Migration SQL](docs/project/designs/facebook-post-page.md#d-fb-post-001--what-is-stored-covers-r-fb-post-003-005-006) · [Legacy restore](backend/src/affiche/shops.py) |
| 3. What the owner saw | **CLOSED** | Admission compares the frozen attempt ID **and state**. The separate `published_at` still exposes an earlier success after a later failure. Ordering by insertion handles a backwards wall clock. [Design §003](docs/project/designs/facebook-post-page.md#d-fb-post-003--publishing-a-post-covers-r-fb-post-002-to-005) |
| 4. Lost admission answer | **PARTIAL · P1** | Key-first replay closes the normal reload race. The cited chat implementation catches a failed storage write and continues from memory. Copying that fallback lets the request leave without a durable key. Require a successful `shopStorage.setItem` before sending, show a refusal on failure, and clear only the matching key. [Device contract](docs/project/designs/facebook-post-page.md#d-fb-post-005--the-page-covers-r-fb-post-001-002-004-006) · [Chat implementation](frontend/src/ChatView.vue) |
| 5. Shop limit | **PARTIAL · P2** | The atomic `posting` check closes invariant 6, including for a forged request. Lowering the limit after admission but before image one still sends files before the final check. Add the limit to the first upload check to cover R-FB-POST-005’s “before anything is sent” line. [Upload checks](docs/project/designs/facebook-post-page.md#d-fb-post-003--publishing-a-post-covers-r-fb-post-002-to-005) |
| 6. Worker ownership | **PARTIAL · P1** | Shielding admission fixes client cancellation. The existing `_RUNNING` holds task objects, while recovery asks whether a **row** has a live owner. If the task associates its row ID after the commit, a concurrent read can declare it dead while it is still sending. Register ownership by `(shop, key)` before admission, retain it through settlement, and make orphan updates conditional on the observed state. Exercise a read immediately after commit. [Design §003](docs/project/designs/facebook-post-page.md#d-fb-post-003--publishing-a-post-covers-r-fb-post-002-to-005) · [Existing registry](backend/src/affiche/posters/facebook_publish.py) |
| 7. Draft and pagination | **PARTIAL · P2** | Failure preserves the draft, but a success in tab A can still erase edits made in tab B. Clear only the submitted draft revision. Resolve saved IDs in chunks because the endpoint stops at 200. **R-FB-PUBLISH-002 also loses coverage here**. With an existing draft, the final-panel shortcut can open another poster’s description. Give the owner an explicit way to publish this poster alone with its saved caption while preserving the existing draft. [Composer](docs/project/designs/facebook-post-page.md#d-fb-post-005--the-page-covers-r-fb-post-001-002-004-006) · [Single-poster requirements](docs/project/requirements/facebook-publishing.md) |
| 8. Thumbnail confirmation | **CLOSED** | The argument holds. R-FB-POST-005 requires the sheet to show the ordered images and the server to send the confirmed bytes. Linked thumbnails cover the first line. `read_png` verifies the bytes, and a mismatch prevents the feed call. Requiring thirty full downloads would add no guarantee. The redundant `posting_at` wall-clock column can also go unless a reader needs it. The deadline uses monotonic time. [Confirmation sheet](docs/project/designs/facebook-post-page.md#d-fb-post-005--the-page-covers-r-fb-post-001-002-004-006) · [PNG verification](backend/src/affiche/posters/exports.py) |
| 9. Shutdown bound | **PARTIAL · P2** | Removing deletions and suppressing the retry fixes the original overrun. The claimed 60-second bound still does not follow from `AsyncClient(timeout=60)`. A response delivering small chunks can keep resetting its read timeout. Put an elapsed-time deadline around the whole call. Expiry during `/feed` must settle `unknown`. [Graph transport](backend/src/affiche/posters/facebook.py) · [Container grace period](deploy/compose.yml) |
| 10. Explanations and actions | **PARTIAL · P2** | The conditions action and suspension guidance are covered. The permanent hint still omits the forbidden characters. State the rule beside the field. Preserve R-FB-PUBLISH-004’s reconnect instruction on a 190, and keep R-FB-PUBLISH-003’s history and outcome controls reachable when the Page is disconnected. After restore, “nothing below” otherwise hides the very post the owner must resolve. Also show « Images envoyées » when `done == count` to avoid « image 4 sur 3 ». [Composer and state text](docs/project/designs/facebook-post-page.md#d-fb-post-005--the-page-covers-r-fb-post-001-002-004-006) · [Existing refusal messages](backend/src/affiche/posters/facebook_publish.py) |

Read-only review. Graph behavior was assessed from the recorded v27.0 proofs. No files changed or live checks ran.

**REJECT**
