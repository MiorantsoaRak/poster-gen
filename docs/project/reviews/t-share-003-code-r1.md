**Storage and isolation.** The input handler assigns the typed value before validation and calls `shopStorage` in the same event, without a timer, watcher, blur handler, or `await`. A reload after that event therefore sees the last successful write. The opening read is synchronous too. Ordinary re-renders and a confirmed-to-confirmed preview replacement for the same poster do not trigger a reread. Switching posters rebuilds the key, writes recheck the bound shop, and sign-out cleanup matches the full shop prefix. Two tabs write only on input, so the last **successful valid edit** wins. I found no caption eviction or wrong-poster write in those paths.
