# Design review r1 — Publish a poster on the shop's Facebook Page (design v1)

Reviewer: Codex, read-only, 2026-11-21. Verdict: REJECT. Not answered by patches: the design is parked until the proofs (see the design's header), then rewritten smaller.

**Draft v1 has three approval blockers in the publish path alone.** It can report someone else’s photo as the shop’s publication, authorize a second send after a successful first one, and publish a different image or to a different Page than the owner confirmed. All three can be addressed without adding persistent browser state.

| **D-002 state consumption, lines 74–84, 149–151** | “Nothing is written until the last step” contradicts consuming `state` before exchange. `store.mutate` holds a write transaction throughout `apply`, rolls back on refusal, and replays a saved response. It cannot implement the described transaction boundaries. Shop-only state also survives a session change within the same shop. A slow callback can finish after disconnect or a newer connection and overwrite the owner’s choice. | Bind the attempt to the initiating live session and shop. Atomically claim it once, checking expiry, **before** Graph I/O. A foreign attempt must leave the rightful attempt intact. Complete only if that same attempt is still current. New connect and disconnect invalidate earlier attempts, including claimed ones. Keep the route’s `Key` dependency and use short transactions as `reads` does. [Mutation implementation](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/backend/src/affiche/posters/store.py:45) · [Live-session check under lock](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/backend/src/affiche/posters/terms.py:55) |

**Direct answer on `mutation_keys`.** For `POST /api/facebook/page`, `mutate` stores a SHA-256 digest over the canonical body and revision, plus the **full successful response**. With exactly the proposed `{page: {id, name, state}}` response, neither the raw OAuth code nor an access token is stored there. `POST /api/facebook/connects` is different. Its saved `{url}` contains the raw OAuth **state**, so deleting `facebook_connects` does not erase every copy, and replay can return an expired dialog URL. The frontend’s generic `mutation()` also keeps the serialized request body, including the callback code, in its in-memory uncertainty map on a network failure. Use an explicit key for the callback, return only allowlisted public fields, and give connect-start an explicit expired-attempt response. [Server persistence](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/backend/src/affiche/posters/store.py:45) · [Browser mutation helper](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/frontend/src/api.ts:275)

**P3 — Migration and proofs.** `0018` is the correct next number. Use the rehearsal’s actual `PRESERVED` and `ADDED` declarations and verify that existing rows survive. Keep stub publications isolated from real history so a simulated success can never appear as a real Facebook link. [Latest migration](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/backend/migrations/versions/0017_terms_acceptance.py:23) · [Existing provider-mode isolation](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/backend/src/affiche/posters/reads.py:572)

The largest simplification is to remove automatic photo matching, the ten-minute failure rule, 30-second polling, and the shop-wide lock. Keep the existing caption editor, one confirmation sheet, one server-side publication record, and a clear unknown outcome. The decisive tests for the next draft are two stale sheets submitted sequentially, a Page or image changed after preview, and a successful upload whose response is lost.

Read-only review of the draft and repository. The supplied Meta facts were taken as given. No files were modified, `backend/.env` was never opened, and no device, store, production or live Meta checks were run.

**Verdict: REJECT.**
