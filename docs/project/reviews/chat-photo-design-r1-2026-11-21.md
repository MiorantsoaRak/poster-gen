# Design review r1 — images on an existing poster (D-TEXT-FIRST-007 v1) and the features warning by words (ADR-125)

Reviewer: Codex, read-only, 2026-11-21. Verdict: REJECT. Answered by D-TEXT-FIRST-007 v2.

**D-TEXT-FIRST-007 needs another design round.** The two existing server mutations are sufficient. The blockers are in the browser handoff between posters and in what a tab running the released bundle can still charge for. ADR-125 also has a French false positive that would reproduce the owner’s complaint.

### P1 — blocks approval

1. **An older tab can pay for a scene that ignores the attached inspiration.** D-007 checks backward compatibility for `photo`, but the other two actionable cards use kinds the released bundle already knows. Open an inspiration-only `restyle` there and `revise` explicitly clears `styleReference`. Open the copy’s `recap` there and `start` takes the editor’s reference, which `adopt` cleared for the version-less copy. Either card can spend its credit without sending the promised image. **Smallest fix:** give paid cards whose execution requires the new reference behavior a kind the released bundle treats as inert. In the new bundle, dispatch those kinds through the existing `revise` and `start` paths, including their existing replay handling. Test both stored cards against the released behavior. [D-007 card table and compatibility claim](docs/project/designs/text-first-generation.md#d-text-first-007--images-on-an-existing-poster-covers-the-adr-126-amendment-of-r-text-first-004) · [paid-card dispatch](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/frontend/src/chat.ts:221) · [start and revise](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/frontend/src/App.vue:1935)

2. **Copy step 5 can lose the only usable recap or overwrite a paid request.** If the source `done` write succeeds and the destination write fails, the source action is closed, and `load` explicitly creates no recap. `importForm` only updates a recap that already exists. In the opposite failure case, the source card can remain open after the destination was used. Retrying the free copy correctly returns the same poster, but unconditionally writing its starter thread replaces its existing recap, potentially including a spent card’s exact request and job. A fresh recap then has a fresh payment key. **Smallest fix:** require verified storage of the stable keys and source revision before either POST. Once the server returns the copy, initialize its thread under `threadKey(copy.id)` only if absent, preserving any existing thread. Verify that write before completing the source card. Keep the copy ID recoverable from the source action, and make retries finish or open that same copy. A storage refusal should leave a recoverable action and a truthful French message. Remove the claimed automatic recap fallback. [Design steps 2–5 and storage fallback](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/docs/project/designs/text-first-generation.md:398) · [load and importForm](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/frontend/src/ChatView.vue:122) · [storeThread](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/frontend/src/chat.ts:211)

3. **The busy guard does not establish chat ownership across `adopt` or `start`.** A takeover can occur during `adopt`’s initial visuals GET. On return, `adopt` can replace `creation`, dispose the saver and change the address in the tab that lost the chat. The creation watcher runs synchronously at the assignment, before the new document and visuals are installed. Separately, `start` waits for the palette and invokes `createScene(key, sending)` without `owned`; the last `sending` check protects the paid POST, but document and plan work can already have run under the old hold. **Smallest fix:** capture the hold token and source thread when the copy starts. Check both before source writes and after waits, and pass the ownership check into adoption and `start` through `createScene`. Write the destination by explicit key before changing `creation`. Let `adopt` set the address once. Its normal hash change already matches `here()` and does not reopen the poster. Also handle a different pending navigation before adoption so the copy does not overwrite the owner’s Back action. [Creation watcher](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/frontend/src/ChatView.vue:392) · [adopt](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/frontend/src/App.vue:1215) · [hash handler](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/frontend/src/App.vue:804) · [start](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/frontend/src/App.vue:1948)

### P2 — should fix

4. **The no-version branch drops an image on an existing poster.** Line 394 consumes the message and answers only « L’affiche n’a pas encore de version. » This contradicts ADR-126’s first bullet and affects the exact poster the new flow creates. A product-photo copy needs a stored revision and an input, both of which already exist. **Smallest fix:** allow the product-copy action without a version. For inspiration alone, use it for the first-image recap, or obtain an explicit requirement exception and retain the attachment with an explanation. Specify that the existing-poster image branch replaces the false « Les photos d’une affiche se changent dans Pas à pas » branch. [Design exception](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/docs/project/designs/text-first-generation.md:394) · [requirements](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/docs/project/requirements/text-first-generation.md:103) · [send](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/frontend/src/ChatView.vue:218)

5. **A retry can seed the right copy with the wrong words, price or style.** The server can replay the original copy response even after the source has changed. Step 5 takes the source’s current values. Brand, subtitle and accent word are particularly vulnerable because they live outside the copied document until a version carries them. `adopt` clears them on input change, and restoring them only after `await adopt()` leaves a close-or-failure window. The chat draft also accepts just three built-in styles, while the editor supports saved styles and `libre`. **Smallest fix:** take title, price, format and identity from the returned copy document. Capture the headline settings and supported style at the same time as `sent.revision`, and restore them by copy ID even on resumed opening. Define what the recap displays for a saved or custom style. Pass the message’s inspiration explicitly on its paid tap. `start` really does skip `createPoster` for an existing creation and proceeds to plan/scene generation, so no extra generation path is needed. [Copy steps 5–6](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/docs/project/designs/text-first-generation.md:401) · [headline reset and restore](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/frontend/src/App.vue:1222) · [stored draft validation](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/frontend/src/chat.ts:130) · [scene generation](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/frontend/src/App.vue:1420)

6. **Same-format `reformat` can change the promised layout.** `copy_creation` already clears the scene and removes the cutout in every layout. `reformat` additionally clamps every layer’s bounds, changes visibility, and replaces the formats map with one entry. Even at the same dimensions it does more than reveal text that was drawn in the old scene. **Smallest fix:** start with the returned copy document and apply only the necessary visibility changes. Specify when they are saved and how opening resumes if that save fails. Verify layer positions, sizes, styling and shop identity on the copy, as well as the original document. [Copy implementation](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/backend/src/affiche/posters/store.py:305) · [reformat](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/frontend/src/document.ts:94)

7. **The locally constructed inspiration card bypasses existing restyle decisions.** The reader sends a poster without drawn words to `steps`. It also tells the owner when earlier scene adjustments will be dropped. The proposed card unconditionally offers « Refaire l’affiche » and omits that consequence. `revise` can refuse when drawn text is disabled, and `again` can re-offer the same unusable action. **Smallest fix:** specify eligibility before showing the paid button, use the same target-version selection as `readOf`, and tell the owner which earlier adjustments the new scene drops. Use the existing `steps` outcome for an unsupported version, with wording that accurately explains what can be done with the attachment. [Image-restyle card](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/docs/project/designs/text-first-generation.md:392) · [reader eligibility](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/backend/src/affiche/posters/reads.py:377) · [adapter refusal](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/frontend/src/App.vue:1959) · [card re-offer](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/frontend/src/ChatView.vue:380)

8. **The source thread’s stored pictures may already be wrong.** The released `send` appends every attachment to `draft.pictures` before choosing the existing-poster branch. A device that experienced the owner’s reported bug can already have the ignored image there. Later recaps render that array, and `inspiration` even includes the current unsent tray. An unrelated attachment can therefore change a recap’s displayed style or the style chosen on tap. **Smallest fix:** on existing posters, build actionable recaps from the actual product input and their explicitly selected reference. Use only the tray for both attachment-role operations. Also prevent a newly filled tray from crossing posters on a copy tap — `load` does not clear it, and adoption’s matching hash bypasses the normal discard prompt. [Released send behavior](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/frontend/src/ChatView.vue:221) · [inspiration computation](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/frontend/src/ChatView.vue:39) · [recap rendering](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/frontend/src/ChatView.vue:535)

9. **ADR-125’s `fiche` matches *affiche*.** The working-tree matcher is unanchored here. « Assombris l’affiche » therefore shows the features warning on an ordinary visual edit. This is more consequential than the accepted « ligne d’horizon » ambiguity because *affiche* names the product itself. Also, the editor design only puts the warning in the confirmation dialog, while the requirement says “as it is typed.” **Smallest fix:** match `fiche`/`fiches` as whole words and use one predicate for the adjacent live warning and the confirmation dialog. Test « assombris l’affiche » and « ajoute une fiche technique », plus typing and deleting the trigger before confirmation. Treat stored `said` and `instruction_fr` as optional, as their type declares. ### P3 — small design and test corrections

- **Free copy action.** `cardButton` already returns `'photo'` to open the file picker. Give the copy button its own action and keep it out of `paid`, `changes` and the paid `reconcile` flow. Guard « Annuler » while the copy is running. For `photo_assets`, explicitly use distinct product-role assets only; keep the inspiration separately. Otherwise a mixed message can submit a style asset as an original, and a repeated product photo is rejected by the input model. [Button handling](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/frontend/src/ChatView.vue:565) · [product input validation](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/backend/src/affiche/posters/models.py:49)
- **French card wording.** “Same title, same price” does not tell an owner who sent several instructions that only the images will be used. Add « Pour un autre changement, envoyez un nouveau message. » On a mixed message, explicitly identify the inspiration as the style of the copy’s first image. [Card wording](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/docs/project/designs/text-first-generation.md:391)
- **Test the interruptions.** The D-007 test line proves the happy path. Add cases for a lost copy response followed by a source edit, failure of each thread write, retry with a spent destination recap, lock takeover during the visuals GET, and reopening a paid image card in the released bundle. Assert actual outgoing keys, `style_reference_asset`, product assets and count of scene requests. These cases distinguish a correct-looking recap from a correct charge. [D-007 tests](/home/miorantsoa/Documents/Miorantsoa/Vite/affiche-ia/docs/project/designs/text-first-generation.md:423)

**Likely ADR-125 misses.** I would add a small set of high-signal phone-shop phrases before expanding the word list further. These are candidate fixtures, not usage measurements.

| Wording | Likely examples |
|---|---|
| French shorthand | « mets les caracs », « ajoute les carac », « mets la config », « affiche la RAM et le stockage » |
| French sales copy | « mets une accroche », « ajoute une légende », « marque “double SIM” en bas » |
| English or mixed | “add key selling points” already matches `selling`; **“add key points”**, **“show the RAM and storage”**, **“add a caption”** and **“put the phone specs”** distinguish misses from the already-covered `specs` |
| Short phone-typed | « rajout config stp », « mets ram/rom », « mtn ajoute 128go », « 3 pts forts svp » |

Prioritize `carac(s)`, `config`, `pts forts`, `accroche`, `caption` and `key points`. Keep « agrandis le téléphone » and « assombris l’affiche » as negative fixtures. The owner already accepted that a fixed list will miss some requests.
