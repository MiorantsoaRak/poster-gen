# Code review r1 — T-FB-010: the « Publier sur Facebook » page

Reviewer: Codex, read-only, 2026-11-21. Verdict: REJECT (five P1, all on the device's second object `post-sent`; three P2). Answered by a change of approach, not by patches to that object: the draft's stamp is the request's key and `post-sent` is gone (design D-FB-POST-005, amended the same day); see r2.

1. **P1 — A late answer can erase another request’s key.** Tabs A and B replay key K. A receives the settled answer and clears K. A new post stores key L. B’s delayed answer for K then calls `forget(SENT)` and deletes L. The refusal path has the same race. Serialize inspection, reservation and conditional removal of `post-sent` across tabs with a shop-scoped lock. Remove it only if the stored key still matches the answer. [ShopPublish.vue:168](frontend/src/ShopPublish.vue#L168) · [ShopPublish.vue:189](frontend/src/ShopPublish.vue#L189) · [ShopPublish.vue:229](frontend/src/ShopPublish.vue#L229)

2. **P1 — An `unknown` replay falls through to a fresh publish.** Leave A unknown, select an unrelated eligible poster B, and confirm. `resend()` calls A `settled` because it is no longer in flight, even though `settled()` deliberately keeps its key. `publishNow()` then overwrites A with B. Retaining A is sound only while the slot remains reserved. Return an explicit `unknown` result, stop this submission, and direct the owner to A’s outcome controls. Only reserve a fresh key after verifying the slot is empty. [ShopPublish.vue:184](frontend/src/ShopPublish.vue#L184) · [ShopPublish.vue:224](frontend/src/ShopPublish.vue#L224)

3. **P1 — Publication can discard an edit the page promised to keep in the tab.** Submit draft S, then edit its description while uploading. If that edit’s storage write fails, memory holds the new stamp but storage still holds S. When S publishes, `answered()` checks only storage and resets the live draft too. Compare the live and stored stamps separately before clearing either copy. [ShopPublish.vue:34](frontend/src/ShopPublish.vue#L34) · [ShopPublish.vue:167](frontend/src/ShopPublish.vue#L167)

4. **P1 — An unreadable `post-sent` is treated as an empty slot.** If reading the key throws, or a nonempty record fails parsing, `resend()` returns `none`. A subsequent successful write replaces the outstanding request with a fresh key. Distinguish absent, unreadable and invalid records. Only absence permits a fresh publish. Give a read failure a retry action and preserve the raw record. [ShopPublish.vue:31](frontend/src/ShopPublish.vue#L31) · [ShopPublish.vue:177](frontend/src/ShopPublish.vue#L177)

5. **P1 — One 503 explicitly deletes `post-sent`.** `export_missing` bypasses the status check, and both callers clear the key. The approved server currently raises this particular error before admission, so the exception has a contract rationale. It still violates this review’s explicit “no 5xx drops the key” invariant. Retain the same key on 503, show the server’s repair instruction, and update the test that currently expects removal. [publish.ts:99](frontend/src/publish.ts#L99) · [publish.test.ts:92](frontend/tests/publish.test.ts#L92)

6. **P2 — Settlement can be lost between two successful reads.** Reopen while a post is uploading. The replay returns `uploading` and schedules a poll. The initial list then returns `published` before the timer fires. `readPosts()` replaces the list and `follow()` cancels the poll. The owner now sees success while both keys and the published draft remain. Route a terminal result for the tracked ID through one settlement handler, including list and stop responses. Refreshing candidates before re-enabling « Publier… » is sound, but a failed refresh currently also re-enables it with stale `seen` values. Keep it disabled until retry succeeds. 7. **P2 — The limit sentence gives the wrong count and remedy.** Lower the limit to two while three posters are selected. The grid says « Votre publication compte 2 images … retirez-en une pour en ajouter une autre. » It contains three, and removing one still leaves it full. Use that sentence only at equality and reuse the existing « Retirez des affiches » instruction above the limit. [ShopPublish.vue:362](frontend/src/ShopPublish.vue#L362)

8. **P2 — Candidate pagination can duplicate tiles.** Two quick taps on « Voir plus » request the same cursor and append both answers, producing duplicate Vue keys and controls. Disable the button while that cursor is loading and discard its answer if a full refresh superseded it. « Voir plus » under *Publications* is sound, since it keeps older unknown posts reachable.
