# Code review r1 — T-FB-004: the restore's Facebook steps, « Vos données », the conditions' new version, the runbook

Reviewer: Codex, read-only, 2026-11-21. Verdict: REJECT (five P1, two P2, all in the public texts, the runbook and the restore script's reminder; no defect found in `after_restore`; the five choices made beyond the design ruled sound). Answered the same day; see r2.

- **P1 — A restore retry can hide a settled publication.** If the first run replaces the database and then fails during startup, rerunning the script sets aside the *restored backup* under a new timestamp. Applying the path printed by the successful retry then compares two copies of the backup. A post made after the backup disappears from the list and can be published again. Preserve the **first** kept path and use it for both the report and `--apply` after any retry. [deploy/README.md:653](deploy/README.md#L653)
- **P1 — The restart instructions can enable Facebook after a refused repair.** A mode conflict makes `--apply` exit 1 with the old connections intact. Step 7 requires only that the command “has run.” On a retry, `app.env` may also already say `off` while the stopped container still has `meta`. Always recreate with `off`, and require a **successful** apply before re-enabling `meta`. **The script’s printed `docker start` reminder must change too.** [deploy/README.md:678](deploy/README.md#L678) · [deploy/restore.sh:81](deploy/restore.sh#L81)
- **P1 — « Sur cet appareil seulement » is false for the caption.** The server stores the submitted caption before contacting Facebook, even when the send never leaves. Limit the device-only promise to the draft and disclose that each admitted publication attempt keeps its caption. [donnees.html:52](frontend/public/donnees.html#L52) · [facebook_publish.py:161](backend/src/affiche/posters/facebook_publish.py#L161)
- **P1 — Both public texts misdescribe the publication record.** « Le lien renvoyé par Facebook » is inaccurate. Facebook returns a post ID, the server builds the link, an owner-confirmed post links to the Page, and a failed attempt has no link. Describe those cases and disclose the retained publication and confirmation IDs, retry key, request fingerprint, timestamps, error code and owner-reported outcome on « Vos données ». [donnees.html:45](frontend/public/donnees.html#L45) · [terms.py:31](backend/src/affiche/posters/terms.py#L31)
- **P1 — The connection disclosure overstates which Pages are kept and when tokens disappear.** Only Pages with `CREATE_CONTENT` enter the choice. An abandoned choice expires after ten minutes, but its tokens can remain in the database until the next cleanup. Successful choice or disconnection deletes the attempt immediately. Say this, mention the stored state and session hashes, and narrow « ne lit rien » to Page *content*: connection reads Page identifiers, names and permissions. Describe disconnection as removing local access and leaving existing Facebook posts alone. [donnees.html:45](frontend/public/donnees.html#L45) · [donnees.html:65](frontend/public/donnees.html#L65) · [terms.py:32](backend/src/affiche/posters/terms.py#L32)
- **P2 — A later credit repair deletes a newly reconnected Page.** The runbook tells the operator to rerun `after-restore --apply` after a pending generation finishes. If a shop has since reconnected, that second apply deletes its new connection and any pending choice. Keep Facebook off and defer reconnection until the **last** credit-repair apply. [deploy/README.md:695](deploy/README.md#L695) · [shops.py:328](backend/src/affiche/shops.py#L328)
- **P2 — Secret rotation does not immediately show every shop « Reconnectez votre Page ».** Only a publish response classified as code 190 marks the matching connection for reconnection. An idle shop keeps its previous state. Tell the operator to recreate after updating the secret and describe the message conditionally. [deploy/README.md:558](deploy/README.md#L558) · [facebook_publish.py:179](backend/src/affiche/posters/facebook_publish.py#L179)

**Choices.** Blocking credits on a mode conflict, reporting and skipping absent shops or posters, and prefixing Facebook report lines are sound. Using the restored database as its own kept copy is sound for clearing connections when the original is genuinely unavailable. Recreating with `off` is sound and simplifies step 7 to one restart path. The « Clé requise » probe precedes shop connection and uses an existing helper.

Static review only. I did not run or count tests, device checks, production commands or network probes.

**REJECT**
