# T-REDESIGN-002 — code review, round 1 (Codex, 2026-11-20)

**Verdict — request changes.** The default chat route bypasses the required unsent-photo question, and opening a recent draft from the drawer can leave keyboard focus on the document body. Both affect ordinary navigation. The passing smokes described by the lead do not exercise those paths.

### High

1. **Unsent photos follow the user into another poster’s chat.** `frontend/src/App.vue:2026` correctly gives a recent poster its `#message-<id>` address when chat is preferred. At `App.vue:741`, however, *every* message address counts as staying in the current chat. `ChatView.vue:119` loads the destination thread without clearing the attachment tray. The smoke explicitly selects « Pas à pas » at `frontend/tests/shop_dashboard_browser.py:1054`, so it exercises only the other address form. **Reject this departure.** Keep the real link and fix the shared route guard to distinguish the current thread from a different poster. On cancel, preserve the address and tray. On confirmed departure, discard the attachments before entering the other thread. Test both preferences and both answers.

2. **A session ended elsewhere can leave the signed-out shop’s poster in the DOM.** `frontend/src/App.vue:2075` clears the shared readers on `out`, but the shop `main` at `App.vue:2239` still renders whenever `loaded` is true. A tab on an editor or library can therefore retain A’s title, image addresses or rows under `hidden` after another tab signs out. The new late-answer test signs out on Accueil, whose component already unmounts on `!shown` (`frontend/tests/shop_dashboard_browser.py:1300`). Render the shop `main` only while `loaded && state !== 'out'`, retaining the existing `hidden` behavior during verification. Keep any same-shop save recovery in memory. Exercise external sign-out from a populated editor or library and check the markup before B signs in.

### Medium

3. **Opening a different recent draft has no destination focus.** `frontend/src/App.vue:753` returns from the poster-ID branch before the focus operation at line 762. The drawer becomes inert, and opening an ordinary draft supplies neither a focused heading nor a dialog. Give the chat and editor headings `tabindex="-1"` and focus the destination after a successful poster route unless a dialog owns focus. Test a *different*, unconfirmed recent poster. The current-row case and the Styles heading test cover different branches.

4. **The sidebar keeps failed recent results and can show an obsolete count.** `frontend/src/App.vue:42` reads `recent.data` even after a refresh fails. `sectionRead` deliberately retains the last successful data, so previously visible links survive contrary to D-REDESIGN-002. Separately, `App.vue:2027` always prefers `activeTotal` once the library has loaded. Visit Mes affiches, create a poster, and the new recent row can appear alongside the old count. Hide the sidebar section on `recent.error`, preserving Accueil’s retry behavior. Invalidate the older list count on a successful create or copy that does not reload the library. At `App.vue:1165`, trigger the recent refresh immediately after the successful creation POST so a later failure in `adopt()` cannot skip it. Assert the rendered count and recent rows after mutations and after a failed refresh following a success.

5. **The gate can hide its only header control on a phone.** `frontend/src/App.vue:2221` applies the `editing` class even while `shown` is false. `frontend/src/style.css:710` then hides the entire header during verification or external sign-out from a phone editor. Bind the header’s editor class to `shown && editing`, or scope the hiding rule to `:root[data-shell]`. Check that the theme switch remains reachable when the gate closes from the editor.

6. **A notice or error can paint over the open drawer.** The drawer and scrim use stacking levels 32 and 31 at `frontend/src/style.css:288`; `.message` uses 40 at line 324. Making `main` inert prevents interaction but leaves the message painted over the menu. Put the open drawer and its scrim above page messages. Open the drawer with a notice already visible and hit-test the overlap.
