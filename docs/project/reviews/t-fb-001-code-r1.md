# Code review r1 — T-FB-001: settings, migration 0018 and the Graph client

Reviewer: Codex, read-only, 2026-11-21. Verdict: REJECT (five P1, three P2, two P3: all hardening of one module; the migration, the settings and the ordinary rows of the table passed).

Two paths block approval. A malformed OAuth code can reach an exception’s `repr`, and an ambiguous Facebook response can become a definite `failed` or `published` outcome. A false `failed` matters here because it allows another send while the first photo may already be on the Page.

### Checks that passed inspection

In the design’s row order, ordinary 5xx and caught transport errors yield `unknown`; a 200 requires this Page’s ID and an ASCII-digit suffix; a 200 without that ID yields `unknown`, including a 200 carrying error 190. For proper 4xx Graph errors, 190 requests reconnection, every listed limit or blocked code yields `failed`, the permission range and listed refusal codes yield `failed`, and an unlisted integer code stays `unknown` with its code preserved. The existing table tests cover those ordinary cases and assert one send.

Migration 0018 adds only the three designed tables. `PRESERVED = {}` correctly leaves every existing table under full-column rehearsal comparison, and `ADDED` checks that each new table starts empty. The populated-0017 test covers preservation, foreign keys and per-shop key uniqueness. I found no upgrade blocker for an existing 0017 database. The mode guard records the first provider inside the caller’s write transaction and refuses a mismatch.

`off` is the default. Neither `off` nor `stub` requires either Facebook credential. The Facebook validation messages are constant, `SecretStr` masks the secret in settings `repr`, and `load_settings` raises `ConfigError` outside the `ValidationError` handler. I found no Facebook input value reaching `ConfigError` text or `repr`. The change adds no dependency.

Verification was read-only, using source inspection and in-memory parser and request-construction checks. The 204 targeted passes are implementer-reported. I did not run or count the full suite or verify Meta’s acceptance of POST exchanges.

**Verdict: REJECT.**
