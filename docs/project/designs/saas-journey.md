# Design · From offer to confirmed PNG or Facebook post

**Status** Approved for implementation on the owner’s « next », 22 November 2026. Covers [R-JOURNEY-001–007](../requirements/saas-journey.md). The [screen review](../reviews/saas-ux-2026-11-22.md) gives the observed problems and the [tutorial design](first-poster-guide.md) covers onboarding.

[Try the shop mockup](../mockups/poster-journey/index.html) · [Try the operator mockup](../mockups/operator-priorities/index.html). Both use illustrative data. The shop prototype exercises file repair and return, the operator prototype the route to an unresolved grant.

## Overview

The shop keeps its two ways to create an affiche and its existing Vue editor. Both routes end at the same fidelity decision, immutable file preview and choice of destination. A seller preparing a Facebook batch can open one unsuitable poster, resolve the reason and return to the same selection. The local renderer, shop and operator sessions, database and credit ledger keep their existing contracts. The picker adds a paginated read of omitted posters. The single-review amendment extends the existing render and confirmation requests with optional fields.

If approved, this design amends the pre-generation order in [poster-editor](poster-editor.md), the relative prominence of native sharing in [share-poster](share-poster.md), the phone bar and overview order in [app-redesign](app-redesign.md), and the counts-only exclusion list in [facebook-post-page](facebook-post-page.md). All existing export, fidelity, cost, order, Page consent and unknown-send decisions still apply. No schema change or migration.

## D-JOURNEY-001 · Start and resume (R-JOURNEY-001, 007)

Keep the named desktop rail, tablet drawer and five-slot phone bar. On phone the slots are Accueil, Affiches, Créer, Publier, Compte when Facebook publishing is enabled. Styles takes the fourth slot otherwise. Styles remains in the drawer, desktop rail and selection controls. Use the capability already used by the publish navigation. A shop that still needs to connect can reach Publier and start connection there.

On Accueil put « Créer une affiche » with the heading. Immediately below show the existing dashboard’s first poster awaiting review, then a failed generation if present. Use its title, next action and any thumbnail already available for that ID. For a successful empty read, show the first-poster guide or recent work. For a failed read, show the section’s last verification time, explicit unavailable state and retry. Compact a healthy balance behind the header’s credits action. Keep blocked generation, low credit, pending amounts, detailed balance and independent refresh available. Shell navigation never dismisses unsaved account changes silently. Library rows retain open, copy, remove, restore and removed filtering; rare actions share a named row menu. Existing poster and style URLs still open directly.

The protected creations listing also returns `has_current_file`, derived from its existing current-revision confirmation lookup. It is independent of pending fidelity work. Older responses still identify the `confirmed` list state. Opening the file reads the poster’s current confirmation again, with a local notice if it has gone. Opening the review reads the poster’s versions, preferring its selected pending visual, then a pending alternative. Neither action selects a version, renders a file or sends a post.

## D-JOURNEY-002 · Review the actual offer once (R-JOURNEY-002, 007)

After valid input creates a draft, show one preparation view. The summary reads the actual document and selected options: original photos and variant, exact integer price in Ar, title, other verified text, logo/name/contact that will appear, selected format and style. Start with the style/format control reachable and the « Textes » and « Boutique » details collapsed. Expanding either edits the same document. Existing defaults show what will be used before the seller acts. A required field or conflict opens its section, takes focus and blocks generation. An abandoned edit follows existing autosave, revision and retry rules. The start route no longer uses visited tabs as prerequisites. The full post-generation tools, versions, compare, undo, polish, reference import and custom styles remain available.

Beside format selection, name Publication as the direct Page format. The message recap uses the resolved format of its own request, along with the verified amount, photo roles and existing charge control. Neither screen creates a job on entry. Charge, budget, terms and low-resolution confirmations continue through the existing functions. A photo on an existing chat still creates a free copy on request and opens that copy in Pas à pas, where its first scene requires an explicit generation tap. Reuse of a previous format, target or price requires the same checks as on a new draft.

## D-JOURNEY-003 · From fidelity to the exact file (R-JOURNEY-003, 004)

**Single-review amendment, approved by the owner on “make the change and continue”.** This supersedes the two successive decisions described below for the current selected version. The private local rendering path may render that pending scene. Reuse the render, job and confirmation records. The existing render request accepts the selected review_visual_id. The confirmation request can carry that same visual ID and fidelity_checks along with its render ID, digest and warnings. Confirm the fidelity of that specific selected scene and its exact file in one server transaction on an explicit confirmation action, checking the revision, scene, original offer, format, digest, layout warnings and PNG. Roll back both decisions on error. Preserve existing approved scenes and confirmations. A refused or historical comparison remains distinct from the current selection. Both editor and Message open the same review with the source photo, price, exact rendered PNG, correction and output choices. A changed or failed render offers recovery. Double clicks and retries reuse the same confirmation. A failed or delayed response must never download a different file or send a post. Batch repair preserves order and description, and the Facebook composer still requires its separate public send. For the library-only choice, reuse the same confirmation transaction and show the ready file in place. Enable it only when the current preview can be accepted. Announce the confirmed state after the server responds. The other shortcuts name confirmation and their next action. No change to charging or generation consent.

**Previous interaction, retained for context.**

Today App.vue’s `decide` can approve a historical version independently of the version selected for output. Capture the poster ID, chosen visual ID, format and shop binding at the decision. On approval, refresh the versions and present the next action **inside the review**. For the currently selected visual use « Vérifier le fichier final » and « Revenir aux réglages ». For a different approved visual offer its existing explicit selection action first. Rejection preserves its reason and returns to versions. Approving a comparison never silently applies it.

On « Vérifier le fichier final », flush the draft and recheck the active shop, poster, selected visual and format. Reuse a confirmed render only when its format and current revision match the intended file. Otherwise use the existing render admission with the current revision and requested format. The general poster-opening helper can prefer the primary format’s confirmation, so the repair path must enforce the requested format at this boundary. A successful admission follows the existing job to its immutable PNG. The renderer coalesces queued, running and successful jobs for the same poster revision and effective input hash. Rendering uses local Chromium and costs zero credits. Another model generation always requires a separate paid control.

| Shown state | Allowed action and transition |
|---|---|
| Product approved | Inspect final file, select the reviewed version explicitly or return to editing. |
| Render queued/running | Follow its job. Recovery reads the server’s job state and opens only its matching file. |
| Preview ready | Show full-size inspection, framing, words, identity, readability and each warning. Enable « Tout est conforme, confirmer » only after the image loads. |
| Confirmed | Submit the existing explicit confirmation with render ID, PNG digest, all checks and warning IDs, under optimistic revision and idempotency guards. Show ready state after its response. |
| Earlier file, conflict or failure | Label the earlier file or explain the failed operation. Offer retry/reload or the current-file check. Keep an existing historical download clearly identified. |

A late result for another revision, format, poster, shop or closed review cannot navigate the user or mark the current work confirmed. A later edit returns its current output to review. The backend still checks the digest, effective layout, warnings and exact bytes at confirmation.

## D-JOURNEY-004 · Output actions (R-JOURNEY-004, 007)

The ready panel leads with the title and the confirmed format and amount. Directly below, put « Publier sur ma Page » for eligible current Publication files and « Télécharger le PNG » for the confirmed file. On a small phone put these actions before a full-height preview. PNG uses the existing authenticated immutable download URL and needs neither a caption nor a Facebook connection. Signal marks the Page action when available and PNG otherwise. For a confirmed file reached while repairing a batch, the primary is « Ajouter à ma publication », beside the PNG. Direct single-image publishing becomes secondary and leaves the existing batch intact. Opening the one-image composer preserves the separate batch draft and carries the current local caption using the existing single-poster handoff. Another format or a previous file cannot be sent as the current Page image.

A disclosure « Partager dans une autre application » contains the local caption, copy feedback and existing native share control. Its share button still invokes sharing within the user gesture. Keep preprepared JPEG handling, explicit unsupported states and PNG fallback. « Autres actions » holds the next poster, price change and past publications. An uncertain send remains visible and actionable above settled history.

## D-JOURNEY-005 · Named omissions, repair and return (R-JOURNEY-005, 003, 004)

**Proposed API.** Add protected `GET /api/facebook/posts/excluded?limit=20&before=<cursor>` alongside `/candidates`, registered before the dynamic post-ID path. The response is `{items: [{id, name, title, primary_format, reason}], next_cursor}`. Use the current document’s offer title, primary format and original product name as title fallback. Each ID is an active creation of the signed-in shop. The three reasons reuse the candidates query’s existing SQL `REASON` expression and precedence: `other_format`, `changed`, `unconfirmed`. A current confirmed feed file makes the poster eligible even if a newer alternative visual awaits approval. Archived, missing and other-shop items are absent. An ID supplied by a client to the existing resolution endpoint continues to receive its existing opaque `gone` when appropriate.

Filter on reason before limiting. Use the existing newest-first `(created_at,id)` keyset and `creation_cursor` validation. Read limit + 1, return at most the requested 1–50, then issue the last displayed row’s cursor only if another row exists. Prefer a single query joining the current version and product input. Return only the listed scalar fields, with no source images, caption, file, token or Page credentials. All reads use existing authentication, session isolation and error handling. No Graph request and no write. Existing `/candidates` responses and aggregate counts stay compatible.

The composer keeps the description above ordered images. A shorter expanding field retains the character counter and surfaces input errors when relevant. Put « Choisir des affiches » near the selection, keep ordinal and En tête labels, and retain the right-end bin, grip and keyboard arrows. Keep preview and public send as separate actions: « Vérifier la publication » opens the frozen sheet; « Publier » or « Publier à nouveau » sends to its named Page.

Fetch the omitted rows on opening « Affiches à préparer (N) ». Keep « Voir plus » and retries local to that list. Reset its cursor after repair or a full refresh, and ignore late pages from an earlier read or shop. A new or fixed poster can move between lists between requests. Reconcile by ID and refresh before selection and before public consent. Counts belong to their own successful server read and can temporarily differ from a later page. Keep them visibly stale when the refresh fails.

| Current evidence | What the row offers |
|---|---|
| Primary Publication, changed or unconfirmed | Name the missing/stale final file. « Vérifier l’affiche » opens its current poster and shows the first unmet step. If the chosen scene is approved and the export guards pass, offer the final-file check directly. Otherwise surface the missing photo/version, pending job, fidelity review or stale drawn price as appropriate. |
| Other primary format, including one never confirmed | « Préparer au format Publication » opens the format control. Where a feed layout already exists and can be reviewed, offer that file. Otherwise offer the existing format choice or « Refaire en Publication » operation, preserving the source and requiring the usual explicit generation decision on the new copy. |
| Removed or inaccessible while opening | Read the authorized item again, say it is unavailable and offer return to the post. No identifying data is fetched by guessing IDs. |

**Return path.** The batch draft remains the sole source of its description, order, stamp and in-flight post reference. Before leaving, verify its currently displayed contents can be saved and read back through the existing shop-bound storage. A failed write keeps the seller on the composer with the text and retry available. For a single poster, persist its valid current caption using the existing caption key or explain why it must be corrected or copied before a full-page departure. Empty means the old value must really have been removed. An unresolved send must be followed or answered before a new send is offered.

For repair within the app, carry only a validated origin destination (batch or single poster ID), the source shop and, optionally, the poster being repaired in tab memory. For the OAuth full-page round trip, retain that constrained return destination in shop-scoped sessionStorage before redirecting. Offer the account’s Facebook section directly. Clear the marker on completion, abandonment, sign-out or shop switch. Read it only after the same shop has been rebound. Reject malformed values and use the account’s normal navigation. If sessionStorage is unavailable, show the ordinary return route before leaving. The callback retains its existing query cleanup, no-referrer and redirect to Mon compte. It never receives an arbitrary return URL.

After a successful Page choice, offer « Revenir à ma publication ». After a successful batch repair, offer « Ajouter à ma publication » and a plain return without adding. On either path reacquire the existing publish Web Lock, read the latest draft from its owner and reload candidates, marks, Page and cap. Never restore a cached snapshot over changes made by another tab. Only the explicit add tap carries a one-use in-memory intent. Consume it after the fresh reads and while still holding the lock: append the eligible ID to the latest batch only when it is absent and capacity allows. Duplicate taps or an ID already present preserve its existing position. If a check fails, say why and keep the post open for an explicit retry. Reload, ordinary return and tab takeover discard the intent. For a new format copy, use the copy’s actual ID. Preserve relative order of still-eligible items, name any items that became ineligible and keep the description. Cancelling connection or repair also returns without adding or sending anything. A repair started from a single composer returns to that composer without modifying the batch. Single-composer results for a replacement copy identify the copy explicitly before changing targets.

## D-JOURNEY-007 · Shared presentation and verification (R-JOURNEY-001–007)

Use the current Signal tokens, Figtree, outline icons, fields, action sizes and light/dark pairs from [DESIGN.md](../../../DESIGN.md). Keep artwork’s own colours and dimensions. ### Failure handling

| Failure or interruption | Behaviour to verify |
|---|---|
| Upload, paid job or balance check fails | Keep product and draft intact. Show the existing actionable refusal, credit state and safe retry for that request. A navigation or repair link never starts a generation. |
| Network lost after approving, rendering or confirming | Read saved scene, jobs and confirmation for the same shop/poster before retrying. Reuse supported mutation replay. A failed image load blocks final confirmation and a missing export shows download failure. |
| Autosave conflict, format lock or version changed elsewhere | Preserve unsaved user input through the existing conflict path. Show the server’s current state before proposing a new review. A partial format copy resumes its actual saved copy. |
| Browser storage unavailable, damaged batch or another tab owns it | Preserve displayable work, distinguish the three conditions, refuse to overwrite unreadable data and use the existing takeover/retry controls. Never mint a fresh send key to recover an uncertain result. |
| Page disconnected, Facebook consent denied or authorization expires | Keep the batch, show Facebook account recovery and leave history/unknown-post resolution available. Recheck the Page ID before enabling send. |
| Race after opening the post sheet, missing file, lower cap, hung upload or unknown feed result | Use the existing admission checks and outcome protocol. Display the server refusal or follow the existing request to settlement. Require the owner’s explicit observation for an unknown result. |
| Authentication changes or a response arrives after departure | Discard results that no longer match the binding and view. Hide data during revalidation and clear transient navigation context. |
| Operator session ends, financial reply is lost or one overview read fails | Retain unresolved request identity and identify unread sections. Never infer zero, settlement or backup health from missing data. |
