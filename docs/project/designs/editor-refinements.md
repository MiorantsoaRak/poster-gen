## D-EDITOR-REFINEMENTS-001 — Composition inputs

Brand duplication: share a small tested word-sequence rule in Python/TypeScript (NFKD, remove combining marks, lowercase, Unicode letters/numbers; complete contiguous tokens). Preserve offer.title and the recorded headline. New scene compilation skips the separate brand heading if already in title; the UI explains it and shows the unchanged title. Refinements of historical scenes compile with their previous brand behaviour; no silent legacy rewrite. Quote counts use the effective brand.

Palette: a small frontend module samples a downscaled first original photo via same-origin authenticated assets and canvas. Ignore transparent pixels and edge-background-like colours where foreground remains; quantize the remaining pixels, prefer a genuinely dominant family over tiny coloured details, and derive neutral/light/dominant swatches. This is an explicitly labelled photo suggestion, not semantic product segmentation. Manual colour override derives the same three swatches. Display all three in Style, plus retry/manual selection. Palette state is per product/creation, never the remembered global accent; local saved overrides are validated and survive reload (storage failure explicitly reported for manual choices). Discard asynchronous results if the product changed. New scene's plan.palette is exactly the displayed list and its drawn-text accent follows that list in this style; other looks keep their existing accent rules. Include palette in plan cache signature so a retry/new choice cannot reuse an obsolete plan. Failure blocks this style until manual selection/retry/another look; no paid call in sampling.

## D-EDITOR-REFINEMENTS-002 — Identity and logo regions

Start all intake inclusion flags off, reset between products, remove automatic contact/logo opt-in. Save profile independently. In Boutique, an explicit form uses existing PUT /api/shop-profile (If-Match/idempotency); then fills only missing brand_snapshot properties through existing PUT /api/creations. Preserve inclusion switches; user enables details deliberately. Disable form/import during a job. Failed profile save does not mutate document; failed document save uses existing DraftSaver recovery. No new endpoint or snapshot mutation on GET.

Reuse logo ImageLayer x/y/width/height, keep_aspect and asset. A plain logo placed in the top half denotes a corner; exact x/y and bounded box are set by a shared frontend helper for each format. New inclusions default top-right. Explicit existing footer choice remains untouched until a corner is chosen. For a legacy circle with a scene, offer a copy for a new composition, then switch off seal only on that copy before choosing a corner; never alter the original's disc constraints.

PlanContext gains optional `logo_corner: left|right`, omitted when absent to preserve legacy canonical contexts. context_for derives it from a visible included non-circle logo's top-half coordinates. fixed_plan reserves the actual logo footprint on its chosen side at the format's safe top margin, moves the title row below it plus a gap, and verifies remaining product space. validate_plan requires the logo box at that corner, including for revised/Claude plans; an incompatible proposal is refused before a paid image request. Existing plans with no corner keep the current footer layout. compile_scene explicitly reserves the original-logo area; no logo image goes to the generative model.

GET visual gains optional `logo_box` (canvas pixels) only for new corner plans, and `logo_footer_box` for historical footer geometry restored on explicit selection; it is derived from the stored plan/context, not a new DB field. The editor uses it when selecting a version to restore matching placement. A shared backend guard, used by render/export and refinement before enqueue, refuses a top-corner logo without a matching reserved region (or a moved logo in a corner-planned composition). Tolerance 2 px for rounding. Adding/removing a logo leaves commercial text checks intact. Removing a corner logo may leave blank space but is safe; moving a seal still fails its existing disc guard. A same-region logo replacement remains the original file overlay with final review.

New refusal `logo_placement_stale` maps to French guidance to generate a version or restore the reserved position. Client computes the same state to show the reason before a click; server remains authoritative. Existing confirmed PNG downloads and revision history are unchanged. Final review explicitly includes logo/title/product collisions; no promise of model obedience without a paid visual check.

## D-EDITOR-REFINEMENTS-003 — Mobile and accessible editor

Below 500 CSS px of visual viewport height, hide the pinned proof and offer the existing full-screen action; observe visualViewport resize for keyboard space. Otherwise reduce the existing pinned preview to a compact maximum height; keep POSTER_STRIP for typing. Add an accessible show/hide-preview control (aria-expanded) without changing the document. Keep full-screen view. Make the tools row sticky immediately below preview/header using measured CSS offsets; include its height in scroll padding/focus positioning. Avoid adding backdrop filters to ancestors of fixed chrome. Versions receive inner padding for focus outlines, visible numbers and unique choose/compare labels; their normal mobile ordering must not place controls below the initial fold (compact optional versions disclosure if needed).

Title/brand/subtitle errors get stable IDs/aria-describedby, visible 60-character context, and generation-next-version copy. Explain variant and image terminology in ordinary French while retaining established control names where needed. Change cost wording to identify a reservation, not a charge/maximum; keep monetary math/caps unchanged. No invented cost estimates.

## Failure modes and verification

- Same-origin photo download/decode/canvas failure: visible error, retry/manual colour, no paid fallback. A late result cannot change another poster's palette. Stored malformed values are rejected.
- Profile revision conflict/auth/network errors: existing API errors/DraftSaver recovery; no hidden retry or lost draft. Disable generation during unsaved/error states as existing safeguards require.
- Logo corner no longer matches scene: refuse render/refinement before ledger enqueue; preserve chosen/historical scenes. Plan too cramped or invalid corner: refuse visibly before image cost. Model ignores reserved zone: user checks actual final composite; explicit regeneration only.
- A product/scene/format change resets or rehydrates UI-only palette/preview state appropriately. A paid job locks relevant document controls; original-revision adoption remains required.
- Tests: Unicode brand boundary cases; black/white/transparent/red/noise image palette pixels; all-format corner geometry and old footer/seal unchanged; plan validation; render/refinement stale guard and no new call on refusal; original-logo render and confirmed-download preservation. Frontend unit suite, backend full suite, build, updated existing browser smoke plus focused mobile/palette/logo flow with stub providers.
- Real browser: local production build in Edge/Chromium with free data; deployed frontend can only contain changes after the user-controlled committed/pushed release. No production server changes or paid verification without the corresponding authorization.
