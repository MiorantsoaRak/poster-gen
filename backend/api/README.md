# Pilot HTTP contract

Implemented: original uploads, immutable inputs, shop identity, versioned drafts/history/copies, durable jobs/combined spending, fixed or Claude scene plans, GPT scene integration/refinement, fidelity review and owned generated assets. Constrained text proposals and separately requested material effects are implemented. PNG rendering in the three poster formats (Publication 1080 × 1350, Carré 1080 × 1080, Story 1080 × 1920), final confirmation and immutable downloads are implemented; `FORMATS_ENABLED` decides which formats a poster may take. The API scheduler starts automatically under the exclusive API process lock.

The executable OpenAPI contract is generated from `affiche.api.create_app()` and served at authenticated `GET /api/openapi.json`. `tests/test_api.py` exercises the real ASGI app against temporary SQLite/files, with no remote providers or Postman workspace dependency. Run from `backend/`:

```powershell
uv run pytest tests/test_api.py tests/test_poster_drafts.py -q
```

Configure the server-only `APP_ORIGIN` listed in `.env.example`, alongside the existing required spend cap/date. The CLI does not require it. Since migration 0013 each shop's password is in the database: `SHOP_PASSWORD_HASH` is optional and read at one start only, the first after 0013, to become shop 1's (`originalphone`) password; later starts ignore it with a warning. Shops, passwords and credits are the operator's: `uv run python -m affiche.shops list|create|set-password|end-sessions|suspend|enable|grant|move-payment|correct|pause|resume|purchase-text` (it never migrates, so start the API once first; `--help` for each; deploy/README.md "Shops" and "Credits"). `create` grants 5 offered welcome credits (`--welcome N`, `0` for none). A shop starts at zero credits, and an image request then gets 402 `no_credit`: on a new data folder, grant shop 1 some before you make images. `SUPPORT_CONTACT_FR` (optional) is shown under the sign-in form for a forgotten password; `SHOP_DAILY_SPEND_USD` (default 2.00) is each shop's provider spend per UTC day. `FORMATS_ENABLED` (a comma list of `feed`, `square`, `story` that must include `feed`; default `feed`) names the formats a poster may be created in, changed to, planned, generated, refined and exported in; any other is refused with `format_unavailable` before any job or reservation, and `GET /api/capabilities` reports the list (ADR-080: Square and Story stay off until real scenes in them were judged). On a new data folder, start the API once, then give shop 1 a password (printed once):

```powershell
uv run python -m affiche.api
uv run python -m affiche.shops set-password originalphone
uv run python -m affiche.shops grant originalphone 30 --offered --ref dev-start
```

The server binds `127.0.0.1:8000`, uses one process, and believes `X-Forwarded-For` only from a peer on loopback (the one front process: Vite, a tunnel client or Caddy), so the login limit counts the real client (D-HOSTED-PILOT-001). For development, the Vite proxy forwards `/api` and preserves the configured browser Origin (`http://127.0.0.1:5173`). Hosting/proxy setup is separate: HTTPS and an exact trusted proxy policy are required before exposure. Never run this development entry point as a public unauthenticated file server. Existing data folders retain their provider mode and ledger.

Every mutating request requires `Origin: <APP_ORIGIN>`. Authenticate with `POST /api/session {"identifier":"…","password":"…"}` (`X-Affiche-Bundle: 3`); retain the HttpOnly, SameSite Strict cookie. HTTPS origins use Secure cookies. The identifier ignores case, accents, spaces and punctuation. An unknown identifier, a wrong password and a shop without password all get 401 `wrong_credentials`; a suspended shop gets 403 `shop_suspended`, and only after the right password. In 15 minutes, 5 failures for one identifier from one client address, or 20 from the address for any identifier (an IPv6 address counts as its /64), give 429 `rate_limited` with `Retry-After: 900`, including across server restarts. `GET /api/session` answers `{authenticated, shop_id?, support_fr?}`, with `support_fr` in every answer, signed in or not, whenever `SUPPORT_CONTACT_FR` is set (a sign-in form may show while another shop is signed in on the device); `DELETE` revokes the session. `POST /api/session/password {"current_password","new_password"}` (no Idempotency-Key) changes the shop's password under the same limits: it keeps this session and ends the shop's other sessions, and no other shop's; 403 `wrong_password`, 422 `password_too_short` (under 10 characters). A request with `X-Affiche-Shop` naming another shop than the session's gets 409 `shop_changed` (a stale-tab guard, not authentication). A session lasts 90 days and stops working while its shop is suspended. Each shop's staff share its sign-in and its data; no shop sees another's.

The operator's dashboard has its own sign-in, apart from every shop's (D-ADMIN-001). `GET /api/admin/session` answers `{authenticated: false, configured}` or `{authenticated: true, actor, expires_at}`. `POST /api/admin/session {"password":"…"}` (Origin, `X-Affiche-Bundle`) signs in under the shops' limits, counted apart, and sets the HttpOnly, SameSite Strict cookie `affiche_operator` on `Path=/api/admin` for 12 hours; it answers 409 `operator_not_set` until `python -m affiche.shops operator-password` sets the password, which no HTTP route sets or reads. `DELETE /api/admin/session` signs out; `DELETE /api/admin/sessions` ends every operator session, this one included. Every other path under `/api/admin/` needs a live operator session (401): a shop's session never reaches it, and the operator's session is refused (401) on every shop route but `/api/session`. The actor `dashboard:<8 hex>` names a session, not a person. `python -m affiche.api` writes the application's own log lines to stderr from INFO up, among them one line per operator action (`operator action=…`), never a password, a hash or a token.

The dashboard's shop routes (D-ADMIN-003) call the command line's own functions. `GET /api/admin/shops` lists every shop by identifier: `{id, identifier, name, state, has_password, created_at, available, pending, posters, last_poster_at, sessions}`. `POST /api/admin/shops {identifier, name?, welcome}` answers 201 `{shop, password, welcome_line}`: the password is in this answer only. `GET /api/admin/shops/{id}` adds the shop's `limits` for the UTC day (`day_spent_micros`, `day_limit_micros`, `reads_today`, `reads_limit`). `POST /api/admin/shops/{id}/password` answers `{password, sessions_ended}`; `DELETE /api/admin/shops/{id}/sessions` `{ended}`; `POST /api/admin/shops/{id}/suspend` `{changed, cancelled_jobs}`; `POST /api/admin/shops/{id}/enable` `{changed}`. Every write checks the operator session again once it holds the write lock (401, nothing written). A rule of the command line refuses with 409 `operator_refused` and the rule's English sentence in `detail`; a name the profile refuses is 422 `validation_error` (`field: "name"`); an unknown shop is 404. Only the operator's refusals carry `detail`.

The dashboard's money routes call `credits.grant`, `credits.correct` and `credits.move`, under the actor `dashboard:<8 hex>`; no Idempotency-Key, the reference is the key (migration 0014). `POST /api/admin/shops/{id}/grants {credits, origin: offered|bought, ref, note?, amount_ar?, method?}` answers 201 `{line, balance: {available, pending}, headroom: {cap, spent, left, outstanding, unit, cost, images, warning}}` (micro-USD, as `grant` prints it). `POST /api/admin/shops/{id}/corrections {credits, ref, note, amount_ar?, job_id?}` answers 201 `{line, balance}`. `POST /api/admin/payments/move {ref, from_shop, to_shop, note}` answers 201 `{lines: [reversal, grant], balances: {from, to}}`. A request sent again writes nothing more: 409 `already_recorded`, with `detail` and `existing`, the line that holds its place (maybe another shop's, for a bought reference), and for a move `existing.moved_to` `{id, shop_id, identifier}`, the grant it wrote in its destination, or null when the source's correction is an amount fix or another correction. `GET /api/admin/shops/{id}/history?before=&limit=1–50` answers `{items, next_cursor}`, newest first: the shop's lines (`type: "line"`) and every job that took a credit, whatever its end (`type: "job"`, with `credit` and `repaid_by`). `GET /api/admin/payments?start=YYYY-MM-DD&end=YYYY-MM-DD` (whole UTC days, end included; by default the current UTC month) answers `{start, end, received_ar, items}`: the lines that carry ariary, so a moved payment counts once.

Style references use the existing asset upload with `role=style`. The optional `style_reference_asset` is an owned SHA-256, never a URL. Missing, corrupt, wrong-role or cross-shop references are refused before spend and rechecked before dispatch. Image order is base (refinement only), original views, then style reference. Visual responses expose `style_reference_asset` separately from `original_urls`; job provenance retains its immutable hash. Omitting it (or passing null) preserves the previous request and replay contract.

Editor image URLs request `GET /api/assets/{sha}?prepared=true` for upright bounded sRGB PNG copies that preserve alpha. The server renderer uses the same preparation. Original URLs still return the unchanged upload. Build the frontend before rendering (`npm.cmd run build`); install the pinned Playwright Chromium with `uv run playwright install --only-shell --no-remove chromium`. Rendered HTML/JS come only from the trusted dist bundle, all browser network requests are intercepted, and image/font bytes are injected as data. A final PNG is never regenerated on download. Missing/corrupt stored exports return `export_missing` and require restoring their exact bytes.

Text proposal style keys are allowlisted. A new title must match an explicit quoted string in the instruction; a new price must match one unambiguous literal integer Ariary amount. Neither model can edit the scene through this route. Generated material pixels fill locally rendered font glyphs; manual price/font changes reuse the applied texture without calling a provider. Generic saves may reuse applied same-shop effects, but cannot attach proposed/rejected effects.

Text layers and proposal styles accept `font_id: "montserrat-black-italic"` with `weight: 900`; Noto IDs require 400/700. Only price layers accept `price_badge: {fill: "#FFFFFF", border_start: "#009FE3", border_end: "#1853BD"}`; null removes it. The exact grouped amount and smaller upright `AR` share one editable capsule. Null badge is omitted from saved documents, preserving old hashes. Invalid font/weight pairs, badge roles and colours are rejected; manual changes cause no provider call.

Credits: a scene, a refinement and a text material (`/scenes`, `/refinements`, `/text-effects`) each take one credit when admitted, in the transaction that writes the job; a job that ends without an image gives it back. With none left the request gets 402 `no_credit` (its sentence, then the purchase text; not retryable) and nothing is written; a replayed key gets its stored answer. The service's pause and its cap refuse every new request to the AI (images, plans, styles, text proposals, chat reads) with 429 `budget_exhausted`, the shop's day with 429 `shop_daily_limit`, both before the credits; admitted jobs finish, a provider's 429 retry included. Chat reads are limited to 100 a day per shop, whatever its credits.

All mutations except uploads, session actions and accepting the conditions require a UUID `Idempotency-Key`. PUT and abandon also require a strong `If-Match`, such as `"2"`. Missing revision → 428; stale → 409 with `error.current_revision`. Replay with the same key, body and revision returns the original result, even if the current revision changed; reusing a key for another request → 409. Failed mutations do not consume the key. Uploads deduplicate by content hash.

Prices are JSON integers from 0 through 9,007,199,254,740,991, never strings, floats or booleans. Unknown properties and canvas-library objects are rejected. Text layers bind title/price/shop roles; there is no second free-form price string. Originals remain byte-identical; colour validation never runs cutout/rembg. Accepted files: static JPEG/PNG/WebP, at most 10 MiB and 40 million pixels. JSON requests are capped at 128 KiB; multipart overhead is separately bounded, including requests without Content-Length.

All errors use `{error:{code,message_fr,retryable,field?,current_revision?},request_id}`. Responses have `Cache-Control: no-store`, `X-Content-Type-Options: nosniff` and a server-generated request ID. Passwords, original bytes, commercial information, SQL and filesystem details are never echoed in error payloads/logs. Persisted sessions contain token hashes only. Storage failures return 503 and preserve earlier committed versions.

References checked during implementation: [FastAPI password hashing](https://fastapi.tiangolo.com/tutorial/security/oauth2-jwt/) and [file uploads](https://fastapi.tiangolo.com/tutorial/request-files/). Installed FastAPI 0.162.2, Starlette 1.10.0, pwdlib 0.3.1 and Uvicorn 0.54.0 signatures were checked; the uv lockfile pins dependencies. Cookie sessions intentionally follow the approved local contract rather than the tutorial's JWT example.

Editor refinements (ADR-085): corner plans reserve the uploaded original logo above the title. Optional internal `PlanContext.logo_corner` is omitted when absent, preserving legacy canonical bytes. Render/export and refinement reject moved corner logos or changed framing with 409 `logo_placement_stale`; the legacy `logo_disc_uncovered` guard also runs before refinement. Preparation and local photo-palette sampling do not call the image provider.
